# 私宴点菜系统

这是一个双端网页点菜系统：宝宝端负责菜单设置、接单、完成订单；宝贝端负责选菜、预约/备注、下单和查看订单状态。

## 启动

推荐直接双击：

```text
start-menu.cmd
```

也可以在命令行里运行：

```powershell
node server.js
```

本机打开：

- http://localhost:3000

## 初始口令

仓库里不会保存任何初始口令、密码哈希、设备绑定或订单数据。

系统启动时会在窗口里显示“宝宝”和“宝贝”的当前口令。进入“宝宝”后，可以在“安全”里修改口令；修改后，下次启动窗口里会显示新口令。

口令明文只保存在本机：

```text
data/local-passwords.json
```

这个文件已加入 `.gitignore`，不会上传 GitHub。

也可以在首次启动前用环境变量指定初始口令：

```powershell
$env:ADMIN_PASSWORD="你自己设置的管理端口令"
$env:CUSTOMER_PASSWORD="你自己设置的顾客端口令"
node server.js
```

每台手机或浏览器第一次输入口令后会绑定设备，之后同一设备不用重复输入；你也可以在“安全”里移除已绑定设备。

## 主要功能

- 菜单设置：新增/删除分类，新增/删除菜品，上传菜品图片，编辑名称、介绍、价格和显示状态。
- 顾客点菜：按分类浏览菜品，调整同一菜品数量，进入确认页选择立刻下单或预约下单，并填写备注。
- 订单确认：顾客确认下单后进入“等待确认”；你这边会收到订单并点击“接收”。
- 自动取消：如果 5 分钟内没有接收，订单会自动变成“未成功”，进入双方历史订单。
- 制作/配送：你接收后，顾客端显示“制作/配送中”；你点击“完成订单”后，顾客端显示“订单已送达”。
- 历史记录：双方都保存订单内容、下单时间、确认时间、完成时间；顾客历史订单里有“再来一次”按钮。

## 异地使用

你们不在同一个局域网时，不能只用 `localhost` 或局域网 IP。需要把这个 Node 服务放到一个双方都能访问到的公网地址上，常见方式：

- 部署到云服务器，然后用域名或公网 IP 访问。
- 使用内网穿透工具把本机 `3000` 端口映射到公网地址。
- 部署到支持 Node.js 的平台。

当前项目已经准备了 Cloudflare 临时隧道脚本。双击：

```text
start-all-quick-tunnel.cmd
```

它会同时打开菜单系统和 Cloudflare Tunnel。把 Tunnel 窗口里显示的 `https://xxxx.trycloudflare.com` 地址发给对方即可。

Cloudflare Tunnel 使用系统安装版 `cloudflared`。如果脚本提示找不到 `cloudflared`，请关掉窗口重开；仍不行就重启一次 Windows。

如果想固定网址，需要自己的域名已经接入 Cloudflare。第一次双击：

```text
setup-fixed-tunnel.cmd
```

设置成功后，以后每天双击：

```text
start-all-fixed-tunnel.cmd
```

如果没有自己的域名，`trycloudflare.com` 临时地址不能固定。

拿到公网地址后，两个人都访问同一个地址即可，例如：

```text
https://你的域名
```

如果正式异地长期使用，建议配 HTTPS，并定期更换口令。

## 数据位置

菜单、订单、密码哈希和设备绑定只保存在本机：

```text
data/store.json
```

这个文件已加入 `.gitignore`，不会上传到 GitHub。菜品图片会随菜单数据一起保存在本机数据文件里。如果上传很多大图，建议先压缩图片。
